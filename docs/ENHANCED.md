# NekoBox Enhanced

NekoBox Enhanced is a coexistable Android build based on NekoBoxForAndroid. It keeps the upstream UI and profile/subscription model while adding Smart Groups, stricter VPN privacy routing, and rule-set blocking.

## Identity and coexistence

- Application ID: `moe.nb4a.enhanced`
- App name: **NekoBox Enhanced**
- Separate Android data directory and database names.
- Internal service/reload/close broadcast actions are namespaced under `moe.nb4a.enhanced.*`.
- Shortcuts point only to the Enhanced package.
- Content provider authorities continue to use `${applicationId}`, so they do not collide with official NekoBox.
- The upstream signing keystore is not reused. Enhanced release signing must use a separate private key supplied outside the repository.

## Core version

v0.1 keeps the NekoBox-compatible **sing-box 1.12.19-neko-1** core commit.

The Matsuri 1.14.x compatibility branch was evaluated, but sing-box 1.14 removes the legacy DNS server format currently generated by NekoBox's `SingBoxOptions.java` / `ConfigBuilder.kt`. Moving to 1.14 therefore requires an explicit DNS configuration migration rather than a commit-only core bump.

## Smart Groups

A group can be changed to **Smart Group** without creating a separate profile database or import flow. Profiles are still normal NekoBox profiles and can be moved into or out of the group.

Smart Groups persist:

- Current RTT and rolling average RTT
- Jitter
- Bounded HTTP throughput
- TTFB
- Success/failure counters
- Consecutive failures
- Last success/failure/test time
- Composite score
- Current algorithm-selected proxy
- Optional locked proxy ID for future/manual control

### Default score

| Component | Weight |
| --- | ---: |
| Stability | 30% |
| Throughput | 28% |
| Success rate | 20% |
| RTT | 8% |
| Jitter | 8% |
| Consecutive-failure penalty | 6% |

The weights are editable per Smart Group and normalized at runtime.

### Switching safeguards

Default behavior:

- Candidate must improve the score by at least **8 points**.
- Normal switches are limited to one every **120 seconds**.
- **3 consecutive failures** bypass the normal switch interval and allow immediate failover.
- Manual node selection updates Smart Group state and starts the same cooldown, so the background selector does not immediately bounce back.
- Only the group used by the running `currentProfile` can hot-switch a live VPN. Merely browsing another Smart Group tab cannot switch the active VPN.
- When the active upstream interface changes (for example Wi-Fi to cellular), the running Smart Group immediately performs a lightweight RTT-only re-evaluation. The larger throughput probe remains on its low-frequency schedule.

### Test path and traffic

Latency and throughput probes instantiate the candidate profile and call through its sing-box instance. Throughput tests reject a null proxy instance, so they cannot silently fall back to the phone's DIRECT network.

Default probe traffic:

- Manual quick throughput: up to **256 KiB per node**
- Background full throughput: up to **512 KiB per node**
- Health/RTT interval: **15 minutes**
- Full throughput interval: **120 minutes**
- Throughput URL: Cloudflare speed endpoint

The response body is bounded with `io.LimitReader`; the client also requests a byte range and closes the response after the cap.

## Strict privacy mode

Strict privacy is an opt-in VPN mode. When enabled it:

- Forces service mode to Android VPN.
- Captures IPv4 and IPv6.
- Disables LAN bypass at the VPN-builder level.
- Enables DNS routing and FakeDNS.
- Routes remote DNS through the proxy outbound.
- Inserts a high-priority `tun-in -> proxy` rule for VPN-captured apps before ordinary bypass/direct rules.
- Converts ordinary direct-routing DNS decisions to remote DNS while strict mode is active.
- Leaves apps deliberately excluded from the Android per-app VPN outside the tunnel.

For VPN-captured apps, TCP and UDP (including WebRTC/STUN traffic) therefore follow proxy-or-fail behavior instead of falling back to the device network.

### Process-death fail-close

A normal Android app cannot force system-wide VPN lockdown by itself. For protection after the NekoBox process is killed, use the **System VPN lockdown** item in Enhanced settings and enable Android's:

1. Always-on VPN
2. Block connections without VPN

Excluded per-app VPN applications remain intentionally direct according to Android's per-app VPN semantics.

## Blocking rule sets

Enhanced can reject matching routing and DNS requests before strict proxy routing.

Supported entries are one per line (or comma-separated):

- `geosite:category-ads-all`
- Other `geosite:...` entries
- `geoip:...` entries
- Remote sing-box binary `.srs` URLs over HTTP(S)

The default list contains `geosite:category-ads-all`, but blocking is disabled until the user enables **Block rule sets**.

Apps excluded from the Android VPN are not routed through sing-box and are therefore not affected by these rules.

## Database migration

The profile database is schema version 7.

v7 adds:

- `smart_group_config`
- `smart_node_metrics`

The migration is declared as Room `AutoMigration(6 -> 7)`. Destructive migration fallback has been removed so a missing migration fails visibly instead of silently wiping profiles.

## Signing

Do not commit a keystore.

The build accepts:

- `KEYSTORE_FILE`
- `KEYSTORE_PASS`
- `ALIAS_NAME`
- `ALIAS_PASS`

If no release keystore is supplied, release assembly may be unsigned. Debug variants use Android's normal debug signing and are suitable for QA installation only.
